## Material corrections

1. **Bind historical Finding assessments explicitly.** [design.md](../design.md), lines 167–194 and 307–309: `Finding` contains mutable outcome, freshness and evidence lists, but no run/manifest binding or pinned control/obligation revisions. `Snapshot.findings` therefore cannot distinguish a terminal run's assessment from a successor's updated Finding without an unstated storage rule. The promise that historical runs stay immutable is insufficient as a shared contract. Add a run-bound assessment reference keyed by project/run/Finding with manifest, Finding revision and exact control/obligation revisions. Return that retained assessment plus a separate current-freshness overlay with its check timestamp. Acceptance: successor retest and registry update leave the old assessment unchanged while current staleness is visible. **R3.9, R5.8, R5.16, R5.20, R6.10.**

2. **Represent unfinished attempts without fabricated outcomes.** [design.md](../design.md), lines 153–158: `state: string` admits undefined states, while mandatory `outcome: Outcome` forces a pending/running attempt to have an assessment already. Specify the execution-state enum and allow an absent/null outcome until disposition. Define the permitted pairs: completed attempts have an outcome; queued cancellation is not-tested; interrupted active work cannot acquire a pass from partial output. Expected/actual observations can likewise remain absent before execution. Acceptance: pending, running, blocked and interrupted snapshots validate consistently through HTTP and CLI without presenting unfinished work as assessed. **R3.10, R5.3, R5.9, R6.12.**

3. **Define cancellation-versus-completion ordering.** [design.md](../design.md), lines 307 and 313–315 specify cleanup but not which result wins when a child completion races cancellation/restart. Conditional result publication must require the same owned attempt still running, a run accepting completion and current authorization/input checks. Serialize that transition with cancellation in the database. Completion committed first remains completed evidence; cancellation committed first rejects subsequent success promotion. Terminal publication additionally requires no active owned check, agent or mutation worker and resolved cleanup; no later callback may append authoritative results to that terminal run. Acceptance A5/A6/A7 should cover these races, not only stopping descendants. **R4.5, R5.9, R5.15, R5.19, R6.12, R7.13.**

4. **Make patch durability ordering explicit.** [design.md](../design.md), lines 321–325: “journal intent” and atomic replacement do not specify durable ordering. Require a committed recovery journal and flushed staged postimage before replacement, then synchronize the containing directory before publishing applied state or starting verification. Synchronization failure leaves recovery/verification blocked, never a confirmed applied action. The Linux manual explains that file `fsync` alone does not ensure directory-entry durability. [Linux fsync(2)](https://man7.org/linux/man-pages/man2/fsync.2.html), retrieved 2026-10-14. Extend A7 to injected synchronization failures; retain the existing exclusive-writer restriction. **R5.6, R5.7, R6.12, R7.13.**
